# 0.5.22 升级审查

本版修复自定义数据库文件名引起的分库问题。43 项测试及 macOS 真实安装升级测试通过。Windows 自动测试已配置，仓库开关目前关闭，实际 Windows 结果仍待授权启用后验证。

## Windows 的两种使用方式

Windows 浏览器访问远端 DSH：打开 DSH 自己的地址，进入「插件 → SuperLcm」。设置请求走当前已登录的 DSH 连接，浏览器不读取 Mac 文件，也不连接另一个本机后台。

Windows 本机运行 DSH：安装依赖宿主提供，数据库目录按当前系统用户和 `DSH_HOME` 解析。运行代码使用 Node.js 的路径和文件网址接口，不依赖某人的用户名、Mac 安装目录或系统软链接命令。本版测试针对 DSH 0.2.1-alpha.1 和 Node.js 22.16 以上版本。

## 更新

在目标宿主上执行对应 profile 的官方安装命令，例如 Windows PowerShell：

```powershell
dsh plugin --profile web add ".\SuperLcm-0.5.22.tgz"
```

然后重启该 DSH 宿主。插件设置页只包含「摘要设置」和「压缩」。更新保留已保存的摘要设置、宿主模型列表及原文和摘要数据库。

若使用共享 SuperLcm 的旧全局接入，先取消该接入，再安装独立包。已有独立 `SuperLcm` 包直接更新。另行配置的历史引擎或工具补丁按 README 退出旧入口，避免重复挂载。

## 审查修复

- 原文归档、压缩节点和运行状态统一使用用户指定的确切数据库文件名。
- 旧版写在旁边 `lcm.sqlite` 的节点和准备草稿，仅对所选数据库已知会话恢复。原文件保持只读，冲突会报警并保留现有数据。
- 已完成和已丢弃的旧草稿不会重新激活。两个宿主同时写入时，恢复操作不会把新数据改回旧数据。
- 旧来源损坏时报警并继续挂载原生压缩保护。
- 安装测试从旧发布代码打包，经官方安装命令启动，更新新包后由新宿主接口读回旧摘要和完整原文。

运行代码及发布配置未发现个人绝对路径。历史变更记录中的旧部署路径只是历史说明，不参与运行。

完整验证范围见 [VALIDATION.md](./VALIDATION.md)，结构化结果见 [RELEASE-0.5.22.json](./RELEASE-0.5.22.json)。
